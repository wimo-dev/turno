`turno-browser` is the command of the turno-browser package: the identity commands on their own, without turno. Inside turno the same commands run as `turno browser <command>` (see [turno browser](/docs/reference/cli/browser)); `setup`, `secret` and `background` are turno-browser's alone, and its `do` goes through the identity's background server instead of mcpd.

## turno-browser init

```text
Usage:
  turno-browser init [--identity <id>] [--agent
      <claude-code|codex|cursor|copilot|gemini|json|none>] [--url <url>]
      [--policy-file <file>] [--no-login] [--yes] [--dry-run] [--json]
    set up step by step: an identity, a sign-in by hand, and your agent (asks
    first)

Sets up a browser identity and gives it to your agent, asking at each step:
  1. the identity's name (a new one is created; an existing one is used as it is)
  2. signing in by hand: Chrome opens on the identity's profile (--url opens a first site)
  3. the agent: the agents found on this machine; its mcp add command runs only if you say yes,
     and an agent without one (cursor, json) gets the block to paste

--yes answers yes to every step, --no-login skips the sign-in, --agent none skips the agent.
--policy-file gives the identity a policy (allowed hosts, disabled features; see set --help),
checked before anything is created and applied in step 1, also to an identity already here.
Without a terminal (--no-input, a pipe or an agent session) it needs --identity and --agent and
skips the sign-in; it prints the agent's command, or with --yes runs it. An agent that already
has the identity's server is left as it is, so running init again changes nothing.

--json prints one report (what was created, the sign-in, the agent's registration with the
command it ran, its exit code and output) and never asks; it needs --identity and --agent.
Exit codes: 0 done, 1 the agent's command failed, 2 a missing answer, 127 --yes and the agent's
program is not on the PATH.
```

## turno-browser set

```text
Usage:
  turno-browser set <id> [--timezone <zone>] [--locale <tag>] [--languages
      <tag,...>] [--region <CC>] [--health-url <url>] [--health-text <text>]
      [--health-selector <css>] [--health off] [--no-health] [--tabs-max <n>]
      [--tabs-popups close|keep] [--tabs-park <duration>] [--tabs-close
      <duration>] [--no-tabs] [--background-throttling true|false] [--settle
      <duration>] [--resources normal|low|auto] [--block-trackers true|false]
      [--block-types image,media,font] [--block-patterns <host|glob>,...]
      [--no-block] [--cache] [--cache-max-size <size>] [--no-cache] [--humanize
      auto|off|light|full|adaptive] [--cursor auto|on|off] [--notify true|false]
      [--last-click true|false] [--sharing session|tabs] [--tab-lock-wait
      <duration>] [--tab-lock-release <duration>] [--engine chrome|lightpanda]
      [--attach auto|<dir>|<url>] [--record-flows true|false] [--record-traces
      true|false] [--record-screenshots true|false] [--record-max-size <size>]
      [--no-record] [--act] [--act-sampling true|false] [--act-provider
      chat-completions] [--act-endpoint <url>] [--act-model <name>] [--act-key
      keychain:<item>] [--act-max-steps <n>] [--act-max-tokens <n>]
      [--act-timeout <duration>] [--no-act] [--captcha-provider task-api]
      [--captcha-endpoint <url>] [--captcha-key keychain:<item>]
      [--captcha-timeout <duration>] [--no-captcha] [--live true|false|auto]
      [--live-wait <duration>] [--no-live] [--user-agent coherent|auto|off]
      [--proxy-server <url>|off] [--proxy-username <name|keychain:item>]
      [--proxy-password keychain:<item>] [--no-proxy] [--policy-file <file>]
      [--allowed-domains <host,...>] [--disable <feature,...>] [--auto-submit
      true|false] [--no-policy] [--browser
      chrome|edge|brave|chromium|chrome-for-testing|<path>] [--force]
      [--dry-run] [--json]
    change an identity's identity.json (an empty value removes a setting)

Each flag writes one key of identity.json; an empty value (--settle "") removes it, and
--no-health, --no-tabs, --no-block and --no-cache remove a whole group. A flag of a group
changes only its part: the rest of that group stays. A key that is not in identity.json takes
its default at every launch (turno-browser show <id> lists each value and where it comes from);
off pins a key off for good: --health off, --locale off, --user-agent off.

How the host runs this identity's Chrome (read at every Chrome start):
  --resources normal|low|auto     low: the preset for a machine short of memory (at most 2
                                  tabs, idle tabs parked after 2m, Chrome closed after 5m
                                  without a call, a note in tool results when memory runs
                                  low); the flags below still win over it. auto (default):
                                  low while the system reports memory pressure at launch
  --tabs-max <n>                  most tabs open at once, 0 for no cap (default 8)
  --tabs-popups close|keep        close popups the agent did not open (default close)
  --tabs-park <duration>          park an unused tab on about:blank, "0" never (default 5m)
  --tabs-close <duration>         close an unused tab, "0" never (default 15m)
  --background-throttling <bool>  let Chrome slow tabs that are not in front (default: true
                                  in a headless Chrome without the live view, else false)
  --settle <duration>             wait after each action for the work it started, "0" to "10s"
  --block-trackers <bool>         block a built-in list of ad and analytics hosts
  --block-types <list>            block image, media and font requests (never the page itself)
  --block-patterns <list>         block host names (and subdomains) or URL globs with *
  --cache                         keep images, fonts, styles and scripts on disk (100MB)
  --cache-max-size <size>         the cache's size, "1MB" to "10GB"; turns the cache on
  --sharing session|tabs          "tabs" (default): every agent session at once, each in its
                                  own locked tabs; mcp.toml then needs exclusive = false for the
                                  identity's server. "session": one at a time (the default with
                                  --attach)
  --tab-lock-wait <duration>      with tabs: how long a call waits for a tab another session
                                  holds, "0" (fail at once) to "10m" (default 10s)
  --tab-lock-release <duration>   with tabs: a session without calls lets go of its tabs after
                                  this, "0" (free between calls) to "24h" (default 5m)

Blocking without the cache turns Chrome's own HTTP cache off: use them together.

Input:
  --humanize <level>              auto (default): off on localhost and for read-only steps,
                                  light for other actions, full on sign-in, payment and support
                                  pages and on a site after a challenge page there; off, light
                                  (the pointer travels a curve to a point inside the target,
                                  keys typed with human delays), full (plus overshoot, reading
                                  pauses, wheel scrolling) or adaptive (light, full after a
                                  challenge page)
  --cursor auto|on|off            the agent cursor. auto (default): when the browser can be seen
                                  (a window, or the live view), Chrome itself highlights what the
                                  agent acts on and shows its clicks; nothing goes into the page.
                                  on: an arrow with the agent's name that glides to what it acts
                                  on, a ring, click ripples and a frame with a badge, drawn as an
                                  element in each page that a page script can see. off: neither
  --notify true|false             the system's notifications when the agent waits for you (a
                                  person step, a passkey, a captcha) or is done after a long
                                  run. true (default); TURNO_BROWSER_NOTIFY=off also turns them off
  --last-click true|false         true (default): a click that buys, sends, publishes or deletes
                                  is yours: the agent fills in the rest and asks you with
                                  browser_request_human. false lets the agent click it

Which engine runs this identity (all off by default):
  --engine lightpanda             read mode: Lightpanda instead of Chrome, for reading pages;
                                  needs lightpanda on PATH (turno-browser doctor says how)
  --engine camoufox               Camoufox (a Firefox build) with its own profile; needs
                                  Camoufox and playwright-core (turno-browser doctor says how); no
                                  captcha solving, and no picture in the live view
  --attach auto|<dir>|<url>       use the Chrome you have open instead of the identity's own:
                                  "auto" is your default Chrome profile, after you turn on
                                  chrome://inspect/#remote-debugging; Chrome asks you to allow
                                  each connection, and the agent then sees all its windows

What turno-browser records for this identity (turno-browser record):
  --record-flows <bool>           keep every session's actions as a flow (auto-<time>, newest
                                  20; on by default)
  --record-traces <bool>          a Playwright trace of each browser session (turno-browser traces);
                                  by default only the traces with a failed step are kept
  --record-screenshots <bool>     a screenshot after each action (on by default, never of a
                                  page that shows a vault value; not with attach or Lightpanda)
  --record-max-size <size>        cap of the traces and screenshots, "10MB" to "10GB" (default 200MB)
Vault sign-ins and passwords never reach a flow, a trace or a screenshot.

On when something answers them, for your own accounts only (they send page content to a
third party, and many sites' terms forbid them; the server lists their tools from its next start).
Without a provider, natural language actions (browser_act, browser_extract, browser_observe) use
your client's model (MCP sampling), else OPENAI_API_KEY or ANTHROPIC_API_KEY from the environment,
else the Claude Code CLI or Codex on the PATH; captcha solving needs a solver key, here or in
TURNO_BROWSER_CAPTCHA_ENDPOINT with TURNO_BROWSER_CAPTCHA_KEY, and otherwise goes to the person:
  --act                           natural language actions in that order (the same as no group)
  --act-provider chat-completions a model API to use when the client has no sampling, with
  --act-endpoint <url>            its base URL (https, or http on this machine),
  --act-model <name>              the model name it expects and
  --act-key keychain:<item>       its key in the secret store (turno-browser secret set <item>)
  --act-sampling <bool>           false: never ask the client, always use the provider
  --act-max-steps <n>             most actions per call, 1 to 30 (default 10)
  --act-max-tokens <n>            most model tokens per call (default 50000)
  --act-timeout <duration>        longest call, "10s" to "10m" (default 2m)
  --captcha-provider task-api     solve captcha widgets (browser_solve_captcha) through a solver
  --captcha-endpoint <url>        service that speaks the createTask protocol, at this URL,
  --captcha-key keychain:<item>   with its account key in the secret store
  --captcha-timeout <duration>    longest wait for a solution (default 3m)
  --no-act, --no-captcha          remove the group: back to the order above

The live view and take-over (turno-browser live, pause, resume):
  --live <bool>                   serve a view of the agent's tab on 127.0.0.1 and let you pause
                                  the agent to take the controls (from the next server start);
                                  on by default, and the view opens only with turno-browser live <id>
  --live-wait <duration>          how long a paused call waits for you, "5s" to "30m" (default 2m)

Network and user agent (for your own accounts and sites you may automate):
  --user-agent coherent|auto|off  coherent: the installed Chrome's own user agent and client
                                  hints, with this identity's languages and time zone, checked
                                  at every launch (a headless Chrome stops saying
                                  HeadlessChrome). auto (default): coherent in a headless Chrome
                                  only, dropped when the check fails. off: Chrome's own. turno
                                  never takes a typed user agent
  --proxy-server <url>            send this identity's traffic through a proxy: http://,
                                  https://, socks4:// or socks5://host:port; its operator sees
                                  where you go, and sites see its address; off: no
                                  proxy, not even the system's
  --proxy-username <name>         the proxy user name, or keychain:<item>
  --proxy-password keychain:<item> the password, only from the secret store (turno-browser secret set <item>)
  --no-proxy                      remove the proxy (Chrome follows the system's)

What the identity may do (a policy; only this command writes it, no agent tool can):
  --policy-file <file>            the whole policy from a JSON file, like
                                  {"allowedDomains": ["example.com", "*.example.com"],
                                   "disabled": ["captcha"], "autoSubmit": false}
  --allowed-domains <list>        the hosts its pages may show: example.com, *.example.com
                                  (subdomains), localhost:* (any port), host:8443; every
                                  navigation of every tab is checked, a page's own scripts,
                                  images and data are not
  --disable <list>                features that do not exist for it: act, captcha, login, totp,
                                  attach, evaluate, run_code, network
  --auto-submit false             browser_login never submits, whatever vault submit says
  --no-policy                     remove the policy
Any policy turns browser_run_code_unsafe off, and allowedDomains the network tools. The server
reads the policy when it starts.

Which browser opens the profile (read at every browser start; turno-browser doctor lists the installed ones):
  --browser <name|path>           chrome (the default), edge, brave, chromium, chrome-for-testing
                                  (turno-browser install-browser downloads it, no admin password), or the
                                  absolute path of another Chromium-based browser. A server's own
                                  --browser or --executable-path wins over it
  --force                         switch the browser of a profile another browser already opened:
                                  the cookies carry over with the default keychain, but the new
                                  browser rewrites the profile and an older one can refuse it

Examples:
  $ turno-browser set school --health-url https://mail.example.com/ --health-text Inbox
  $ turno-browser set school --tabs-max 5 --tabs-popups keep --settle 250ms
  $ turno-browser set school --block-trackers true --cache --json
  $ turno-browser set school --humanize light
  $ turno-browser set school --sharing tabs
  $ turno-browser set school --live true
```

## turno-browser remove

```text
Usage:
  turno-browser remove <id> [--yes] [--dry-run] [--json]
    delete an identity and everything it left on this machine (asks first)

Deletes everything turno-browser keeps for the identity, after it shows the list and asks:
  - it stops the identity's background server, a Chrome on its profile and the
    turno-browser-mcp processes started for it (nothing is deleted while one still runs)
  - it takes the identity's MCP server out of each agent that has it, with the agent's own
    command (claude mcp remove --scope user browser-<id>, codex mcp remove ...)
  - it deletes the vault's credentials and the keychain: items identity.json references from
    the secret store, unless another identity or turno's mcp.toml uses them too
  - it deletes the profile, identity.json, the vault index, the state folder, saved flows and
    the session exports it wrote

--yes deletes without asking; without a terminal it is required. --dry-run shows the list.
Afterwards it checks that nothing is left. Exit codes: 0 all gone, 1 something is left (--json
lists it under left, with the step that removes it), 2 no terminal and no --yes.

Examples:
  $ turno-browser remove school --dry-run
  $ turno-browser remove school --yes --json
```

## turno-browser setup

```text
Usage:
  turno-browser setup <claude-code|codex|cursor|copilot|gemini|json>
      [--identity <id>] [--json]
    print the MCP config that gives an agent an identity (Claude Code, Codex,

Prints how a coding agent gets one identity's browser: the command to run, or the block to
```

## turno-browser vault

```text
Usage:
  turno-browser vault add <identity> <site> --url <sign-in page> [--url
      <url>]... [--username <name>] [--totp] [--dry-run]
    store a site's username, password and optional TOTP secret (asked hidden, or
    on stdin)
  turno-browser vault list <identity> [--json]
    the sites in an identity's vault (never the values)
  turno-browser vault remove <identity> <site> [--dry-run]
    delete a site's credentials
  turno-browser vault submit <identity> <confirm|auto> [--dry-run]
    let browser_login submit the form (auto) or leave the click to the agent
    (confirm, default)

The vault keeps a username, a password and optionally a TOTP secret per site for one
browser identity, only in the secret store (the macOS Keychain or the Linux Secret Service).
The browser_login tool fills them into the site's sign-in page without the agent seeing them,
and only on the origins given with --url. In a terminal the password and the TOTP secret are
asked with hidden prompts; from a pipe, the first line of stdin is the password and, with
--totp, the second line is the TOTP secret (base32, or the otpauth:// URI of the QR code).

Examples:
  $ turno-browser vault add work github --url https://github.com/login --username alice --totp
  $ printf '%s\n' "$PASSWORD" | turno-browser vault add work mail --url https://mail.example.com --username alice@example.com
  $ turno-browser vault list work
  $ turno-browser vault list work --json
  $ turno-browser vault submit work auto
  $ turno-browser vault remove work github --dry-run
```

## turno-browser secret

```text
Usage:
  turno-browser secret set <item>     store a value read from a hidden prompt or
                                      stdin
  turno-browser secret has <item>     exit 0 when the item exists
  turno-browser secret list [--json]  every keychain: reference in identity.json
                                      and whether it is stored
  turno-browser secret remove <item>  delete the item

An identity.json names a secret as "keychain:<item>" (proxy.password, act.key, captcha.key), and
so does a replay parameter (--param password=keychain:<item>). The store is the login Keychain on
macOS, the Secret Service (libsecret's secret-tool) on Linux and files encrypted with DPAPI for
the current user on Windows (%LOCALAPPDATA%\turno\secrets), the same items turno secret uses.
Values are never printed and never passed as an argument. Sign-in credentials live in the vault
(turno-browser vault).

Examples:
  $ printf %s "$PROXY_PASSWORD" | turno-browser secret set proxy-password
  $ turno-browser secret has proxy-password
  $ turno-browser secret list --json
  $ turno-browser secret remove proxy-password
```

## turno-browser record

```text
Usage:
  turno-browser record <id> [--flows] [--traces] [--screenshots] [--max-size
      <size>] [--off] [--dry-run] [--json]
    what an identity records (flows, traces, screenshots); turn it on or off

With no flag, shows what the identity records and where. --flows, --traces and --screenshots
turn those on (the next Chrome start uses them), --off turns everything off; turn one off with
turno-browser set <id> --record-traces false. All are off by default.

  flows        every session's actions saved as a flow (auto-<time>, newest 20 kept)
  traces       a Playwright trace of each browser session (turno-browser traces)
  screenshots  a screenshot after each action

Vault sign-ins never reach a flow, a trace or a screenshot: the trace stops before a fill and
starts again after the page navigates, and a password or one-time code is never saved.

Examples:
  $ turno-browser record school --flows --traces
```

## turno-browser live

```text
Usage:
  turno-browser live <id> [--no-open] [--tab] [--json]
    watch the agent in an identity's browser and take the controls (opens the
    live view)

Shows what the agent is doing (paused or not, its tabs) and opens the live view as an app
window of your Chromium browser (your default one, else Google Chrome; --tab opens a tab of the
default browser instead): the agent's tab as a picture next to a timeline of its steps, and Pause
and Hand back buttons. Your clicks, keys and scrolls on the picture go to the page; while the agent
works they take the controls first, and it goes on a few seconds after your last input. The view
is served on 127.0.0.1 only; the link it opens works once. On by default for a server with an
identity: turno-browser set <id> --live false turns it off.

Read mode (Lightpanda) has no pixels, attach mode is your own Chrome, which you already see, and
Camoufox (Firefox) has no Chrome screencast: there the view is off, and pause and resume still work. A page that holds a vault or password
value is never shown until it navigates.

Examples:
  $ turno-browser live school
```

## turno-browser pause

```text
Usage:
  turno-browser pause <id> [--json]  pause the agent in an identity's browser:
                                     its next call waits until you resume

A call that is running finishes; the next one waits up to the identity's live wait (2m by
default), then fails and tells the agent you still have the browser. A batch or replay stops at its
next step. In a headed Chrome the agent's tab comes to the front. Needs the live view on.

Examples:

```

## turno-browser resume

```text
Usage:
  turno-browser resume <id> [--json]  give the browser back to the agent; each
                                      waiting call is told what changed

The waiting calls go on. Each starts with a note: how long the pause lasted and what changed
(the current tab's URL and title, tabs opened and closed, your input in the view). When something
changed, a call that does more than read does not run, and the agent gets a fresh snapshot instead.
The live view's Hand back button does the same.

Examples:
  $ turno-browser resume school
```

## turno-browser do

```text
Usage:
  turno-browser do <id> <action> [args] [--session <name>] [--json]

Runs one action on the identity's browser through its background server, a turno-browser-mcp
that serves the identity to the shell (turno-browser background shows it). The first action starts
it; it exits after 15 minutes without a request (TURNO_BROWSER_BACKGROUND_IDLE changes that). While
it runs it alone drives the identity's browser: an agent's turno-browser-mcp for the same identity
answers with an error that names it. With turno installed, turno browser do goes through mcpd
instead.

Actions:
  open <url>                              go to a URL in the session's tab
  back                                    go back in the tab's history
  snapshot [<ref>] [--depth <n>]          the page's accessibility tree with
                                          refs (e12) to act on; <ref> limits it
                                          to one element
  read [<ref>] [--max-chars <n>]          the visible text of the page or one
                                          element (first 20000 characters;
                                          --max-chars 0 for all)
  find <text>                             elements whose text matches, with
                                          their refs
  click <ref> [--double] [--right]        click an element
  type <ref> <text|-> [--submit] [--slowly]
                                          fill a field (- reads the text from
                                          stdin); --submit presses Enter after
  press <key>                             press a key (Enter, Escape, ArrowDown,
                                          Control+a)
  select <ref> <value>...                 choose options of a select element
  hover <ref>                             move the pointer over an element
  wait [--text <t>] [--gone <t>] [--seconds <n>]
                                          wait for text to appear or go, or for
                                          some seconds
  screenshot [--out <file.png>] [--full]  save a PNG of the tab (default: a file
                                          in the temporary folder) and print its
                                          path
  tabs [new [<url>] | select <n> | close <n>]
                                          the browser's tabs (others' marked in
                                          use), or open, pick or close one
  login <site>                            sign in with a vault credential
                                          (turno-browser vault); the value never
                                          reaches the shell
  call <tool> [--args <json>] [--arg key=value]...
                                          any tool of the identity's server, in
                                          this session (browser_batch,
                                          browser_fill_form...)
  close                                   close the session's tabs (the whole
                                          browser when it serves one session)
                                          and end the session
  session                                 which session these commands use, who
                                          owns it and how it ends
  end                                     end the session now: its tabs stay
                                          open and free, the browser keeps
                                          running

Refs (e12) come from the last snapshot; take a new one after the page changes.

Session: the commands one agent or one terminal shell runs are one session, so they keep their
tab and their place in the tab locks ("sharing": "tabs") or hold the identity's one-session lease
("sharing": "session"). The session belongs to the process that runs the commands: the coding
agent (each of its shell commands passes through a short-lived shell) or your terminal's shell.
It ends when that process exits, with 'end' or 'close', or when the background server exits.
--session <name> (or TURNO_BROWSER_SESSION) keeps several sessions apart under one owner, for
example two subagents each in its own tab.

Output: url: and title: lines, then what the action returned; errors go to stderr with exit 1.
--snapshot after an action prints the snapshot too; --json prints one object.
--timeout <seconds> (default 120) bounds one action; attach mode can wait for Chrome's consent
dialog.

Examples:
  $ turno-browser do school open https://example.com
  $ turno-browser do school snapshot
  $ turno-browser do school click e12
  $ turno-browser do school type e5 'alice@example.com' --submit
  $ turno-browser do school read
  $ turno-browser do school screenshot --out page.png
  $ turno-browser do school end
```

## turno-browser-mcp

The MCP server an agent runs for one identity. `turno-browser-mcp --help` also lists the Playwright MCP flags it passes on, left out here.

```text title="turno-browser-mcp --help"
turno-browser-mcp: a browser MCP server that drives your installed Chrome, with one
persistent profile per identity (turno-browser add <id>).

Which browser: the identity's identity.json browser (chrome, edge, brave, chromium,
chrome-for-testing or a path; turno-browser set <id> --browser), else Google Chrome. The
Playwright MCP flags --browser and --executable-path win over identity.json for this server.

  --identity <id>          use the identity's saved profile (every agent session at once, each
                           in its own tabs, unless the identity's "sharing" is "session" or it
                           attaches to your Chrome)
  --allow-http-identity    allow --port or --host together with --identity; the server then
                           binds to 127.0.0.1 only. Any local process can use that browser.

  TURNO_BROWSER_IDLE=15m   close Chrome after this long without a tool call (headed too); the
                           next call opens it again with the same profile. "0" keeps it open.
                           --idle-timeout <ms> and a --config of your own take precedence.
  TURNO_BROWSER_SNAPSHOT=full|compact
                           full: page snapshots as Playwright writes them, not compacted;
                           compact: no changes on an action's result (default: compact, a
                           table of contents for a long page, and an action that stays on the
                           page answers with what changed; browser_read reads a part, or the
                           whole page with full: true)

Tabs (these flags win over the identity's identity.json):
  --max-tabs <n>           most pages open at once, the least recently used closes past it
                           (default 8; 0: no cap)
  --popups <close|keep>    close popups that open while no tool call runs (default close)
  --park-after <duration>  park a page unused this long on about:blank; it loads again on its
                           next use (default 5m; 0: never)
  --close-after <duration> close a page unused this long (default 15m; 0: never)
  --background-throttling  let Chrome slow down tabs that are not in front (default: on in a
                           headless Chrome without the live view, off otherwise); the agent's
                           tab is brought to the front before each call
  --sharing <session|tabs> "tabs" (default): several agent sessions use the browser at once,
                           each in its own tabs, which it locks (mcp.toml then needs
                           exclusive = false for this server); "session": one at a time (the
                           default with --attach)
  --resources <normal|low|auto>
                           auto (default): low while the system reports memory pressure at
                           launch. low: the preset for a machine short of memory: at most 2 tabs,
                           pages parked after 2m, Chrome closed after 5m without a call (unless
                           TURNO_BROWSER_IDLE says otherwise), the background server gone after
                           5m, and a note in tool results while memory is low. The flags
                           above still win over it

Input (wins over the identity's identity.json):
  --humanize <level>       auto (default), off, light, full or adaptive: the pointer travels a
                           curve to a point inside the target, keys are typed with human delays;
                           full adds overshoot, reading pauses and wheel scrolling; adaptive is
                           light, and full on a site that showed a challenge page; auto is off
                           on localhost and for reading, light to act, and full on sign-in,
                           payment and support pages and on challenged sites
  --cursor <auto|on|off>   the agent cursor. auto (default): when the browser can be seen (a
                           window, or the live view), Chrome highlights what the agent acts on
                           and shows its clicks, with nothing in the page. on: a named arrow,
                           a ring, click ripples and a frame with a badge, as an element in
                           each page that a page script can see. off: neither

Engines (these flags win over the identity's identity.json; all off by default):
  --engine lightpanda      read mode: Lightpanda instead of Chrome, for reading pages
                           (navigate, snapshot, find, click a link, evaluate); other tools are
                           refused. Needs lightpanda on PATH or TURNO_LIGHTPANDA_PATH
  --engine camoufox        Camoufox (a Firefox build) instead of Chrome, with its own profile;
                           off by default. Needs Camoufox and
                           playwright-core (turno-browser doctor says how); never downloaded
  --engine chrome          the default; turns off an identity's read, Camoufox or attach mode
  --attach <target>        connect to a Chrome you already have open instead of launching
                           one: "auto" (your default Chrome profile, after you turn on remote
                           debugging at chrome://inspect/#remote-debugging), a Chrome user
                           data dir, or a loopback endpoint. The agent sees every window of
                           that profile; turno closes only the tabs it opened

Live view (on by default with an identity; identity.json "live": {"enabled": false} turns it off):
  --live                   serve a view of the agent's tab on 127.0.0.1 (turno-browser live
                           <id> opens it) and let you pause the agent to take the controls
  --live-wait <duration>   how long a call waits while you have the agent paused (default 2m,
                           "5s" to "30m"); then it fails and tells the agent you still have it

Background server (for shell use without turno; turno-browser do starts it):
  --background             serve the identity over MCP streamable HTTP on a Unix socket in a
                           folder only you can enter (<state>/browser/identities/<id>/background),
                           or on 127.0.0.1 with a per-server token in a file only you can read
                           where a socket cannot be used. Writes server.json there while it runs.
                           Needs --identity; --port and --host do not apply
  --background-idle <duration>
                           exit after this long without a request (default 15m; "0" never);
                           also TURNO_BROWSER_BACKGROUND_IDLE. Chrome closes first
  While the background server of an identity runs, it alone drives the identity's browser: a
  stdio server of that identity (an agent's, or mcpd's) answers each call that needs the browser
  with an error that names the background server, and the background server does not start while
  another process has the identity's Chrome open. Stop it with turno-browser background stop <id>
  (or kill <pid>); turno-browser background shows which run.

Examples:
  turno-browser-mcp --identity work
  turno-browser-mcp --identity work --max-tabs 4 --park-after 2m
  turno-browser-mcp --identity work --humanize light
  turno-browser-mcp --headless --popups keep
  turno-browser-mcp --engine lightpanda
  turno-browser-mcp --attach auto
  turno-browser-mcp --identity work --live
  turno-browser-mcp --identity work --background --background-idle 30m
```
