This page is for when `turno browser doctor` reports the finding below: what it means and how to fix it.

## What you see

```text
  !  [server.<name>] in mcp.toml lets several sessions in (exclusive = false), but this identity serves one at a time ("sharing": "session"<, the default in attach mode>), so those sessions share one current tab
     fix: turno browser set <id> --sharing tabs
```

It is a warning; warnings do not change the exit code. Words in angle brackets stand for values from your machine.

## Why it happens

mcp.toml runs the identity's server with exclusive = false, so mcpd lets every agent session in at once, but the identity serves one session at a time ("sharing": "session", the default). Those sessions then share one current tab: one agent's navigation replaces the page another is reading. Either give each session its own tabs (the fix below, which keeps exclusive = false), or set exclusive = true for that server in mcp.toml and run turno mcp sync, so sessions take turns.

## Fix

Run:

```sh
turno browser set <id> --sharing tabs
```

`turno browser doctor --fix` does not run it for you, because it needs a decision or an answer from you.

Then run `turno browser doctor` again to see the row turn into `ok`.

The check lives in [`packages/browser/src/doctor.ts`](https://github.com/wimo-dev/turno/blob/main/packages/browser/src/doctor.ts).
