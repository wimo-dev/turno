This page is for when `turno browser doctor` reports the finding below: what it means and how to fix it.

## What you see

```text
  !  patchright-core <version> is not <version>, the version the reputation suite last passed with: how init scripts reach pages and the automation leak checks were not verified on it
     manual: install the turno-browser release as published (its npm-shrinkwrap.json pins patchright-core <version>), or run the reputation bench on this version before relying on it
```

It is a warning; warnings do not change the exit code. Words in angle brackets stand for values from your machine.

## Why it happens

turno-browser drives Chrome with patchright-core and relies on how that release puts turno's scripts into pages without serving the documents itself. Each release pins the patchright-core its reputation suite (automation leak checks, fingerprint consistency) last passed with. Another version, from an override or a manual install, may change that behavior without anyone having measured it.

## Fix

Install the turno-browser release as published (its npm-shrinkwrap.json pins patchright-core &lt;version&gt;), or run the reputation bench on this version before relying on it.

No single command fixes this one, so doctor names the manual step.

Install turno-browser as published, which pins the verified patchright-core in its npm-shrinkwrap.json. If you test a newer patchright-core on purpose, run the reputation bench from the repository on it first.

Then run `turno browser doctor` again to see the row turn into `ok`.

The check lives in [`packages/browser/src/doctor.ts`](https://github.com/wimo-dev/turno/blob/main/packages/browser/src/doctor.ts).
