Esta página responde lo que la gente pregunta antes de instalar turno.

## ¿Está permitido usar varias cuentas?

Depende de tu plan, no de turno. turno ejecuta la CLI oficial de cada proveedor sin modificarla, y cada cuenta inicia sesión con el login del propio proveedor en su propia carpeta. El uso pensado es separar cuentas de trabajo y personales. No lo uses para sortear límites de uso ni salvaguardas; lee [Vendor terms](/es/docs/security#vendor-terms) (en inglés).

## ¿Dónde quedan mis credenciales?

Donde cada agente las guarda, dentro de la carpeta del perfil (o en el Llavero, si el agente lo usa). turno nunca lee, copia ni reenvía tokens de sesión. Los secretos MCP que mueves con `--move-secrets` y los tokens OAuth de servidores MCP remotos van al Llavero de macOS o al Secret Service de Linux. Qué guarda turno y dónde: [Seguridad y privacidad](/es/docs/security#what-turno-stores) (en inglés).

## ¿turno ve mis prompts o el tráfico con el modelo?

No. Lanza el agente y se hace a un lado. Solo las llamadas a herramientas MCP pasan por `mcpd`, en `127.0.0.1` y con un token por perfil, y las peticiones que traen un encabezado `Origin` se rechazan para que una página web no pueda alcanzarlo.

## ¿Linux? ¿Windows?

En Linux también funciona: los secretos van al Secret Service (`secret-tool`), mcpd corre como una unidad de `systemd --user` y los enlaces se abren con `xdg-open`. turno en sí no corre en Windows, pero turno-browser sí, por su cuenta: ve [Get started](/docs/browser/get-started#on-windows).

## ¿Pueden usar turno los scripts y los agentes?

Sí. turno solo pregunta cuando hay una persona en una terminal: con `--no-input` (o `TURNO_NO_INPUT=1`), cuando stdin no es una terminal y dentro de una sesión de agente de Claude Code, Codex, Copilot CLI o Cursor nunca pregunta. Un comando que necesitaría preguntar termina con código 2 y nombra la opción que lo responde:

```text
turno: init needs an answer; pass --yes (or run it in a terminal)
```

`TURNO_NO_INPUT=0` te deja responder en la terminal de un editor que define la variable de un agente.

Un comando que necesita un perfil y no lo recibe (`turno profile assign`, `turno run`, `turno session handoff`, `turno limit set`) muestra una lista para elegir en una terminal (flechas o j/k, escribir para filtrar, Enter, Esc para cancelar). Fuera de una terminal termina con código 2 y lista los perfiles:

```text
pass a profile: personal, work
```

Para scripts, los comandos de lectura aceptan `--json` y los [códigos de salida](/es/docs/reference/exit-codes) son estables.

## Un comando que corre desde una sesión usa otra cuenta. ¿Por qué?

Cada proceso que abre una sesión hereda su cuenta (`CLAUDE_CONFIG_DIR` en Claude Code), y los subagentes de Claude Code corren dentro del mismo proceso, así que la comparten. Dos casos la pierden: `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`, que hace que Claude Code quite la variable de los comandos que ejecuta, y los comandos que rehacen su entorno (`env -i`, `sudo`, contenedores). Entonces un `claude -p` usa la cuenta del agente sin perfil. Deja el scrub apagado, o nombra el perfil en el comando (`turno work -p ...`). `turno config set system ""` le dice a turno que el agente sin perfil no tiene una cuenta tuya, así que `turno auto` se detiene en vez de usarlo. Detalles: [Cuentas](https://github.com/wimo-dev/turno/blob/main/docs/accounts.md).

## ¿Cómo sé si un problema viene de turno?

Abre la misma cuenta sin la pasarela de turno: `turno run work --no-gateway` (o `TURNO_SAFE=1 turno work`). El agente recibe la cuenta y la configuración del perfil, pero sin entradas de mcpd, sin el token de la pasarela y, en Claude Code, sin status line ni hooks. Si el problema desaparece, viene de la pasarela o de la status line de turno; `turno doctor --report` imprime un bloque para pegar en un issue, sin tokens ni valores secretos.

## ¿Cómo lo deshago?

Cada comando que escribe guarda una copia de lo que cambia: `turno undo --list` las muestra y `turno undo <stamp>` las restaura (las copias de más de 30 días se borran, conservando las 10 más recientes).

Para quitar turno, `turno uninstall --dry-run` muestra lo que turno configuró (servicio, lanzadores, entradas MCP, status line, configuración) y `turno uninstall` lo quita; después, `npm uninstall --global turno-cli`. Las carpetas de los perfiles, que guardan tus credenciales, se quedan hasta que tú las borres. `turno uninstall --purge` también borra el estado y las cachés de turno (copias, registros, uso, servidores MCP instalados), y después `turno undo` ya no tiene qué restaurar.

## ¿turno está afiliado a los proveedores de los agentes?

No. turno es un proyecto independiente de código abierto; no está afiliado, respaldado ni patrocinado por ninguno de ellos. Ejecuta las CLI oficiales de los proveedores, sin modificarlas.
