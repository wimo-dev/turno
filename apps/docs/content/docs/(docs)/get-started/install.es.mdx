Esta página instala el comando `turno` y te dice cómo actualizarlo y quitarlo.

## Requisitos

- macOS o Linux. turno no corre en Windows; turno-browser sí, por su cuenta ([Get started](/docs/browser/get-started#on-windows)).
- Node 22.11 o más nuevo.
- Al menos uno de los agentes con los que funciona turno: Claude Code, Codex CLI, GitHub Copilot CLI o Cursor CLI.

## Instala la CLI

El paquete de npm se llama `turno-cli`; el comando que instala es `turno`.

<Install pkg="turno-cli" />

Revisa que quedó:

```sh
turno version
```

`turno upgrade` actualiza turno después con la misma herramienta que lo instaló. CI instala la versión empaquetada con cada una de estas en macOS y Linux y la ejecuta.

- El paquete no ejecuta scripts de instalación, así que pnpm y bun, que bloquean los scripts de las dependencias por defecto, no piden aprobación.
- npm y Homebrew instalan exactamente las versiones de dependencias que se probaron, desde el `npm-shrinkwrap.json` del paquete. pnpm, bun y yarn no leen ese archivo: instalan las mismas dependencias directas (fijadas a versiones exactas) y resuelven por su cuenta las dependencias de esas.
- pnpm 11 y posteriores esperan un día antes de instalar una versión nueva (`minimumReleaseAge`), así que una versión llega a pnpm un día después que a npm.
- yarn quiere decir yarn 1 (classic). yarn 2 y posteriores no instalan global: ahí usa npm, pnpm o bun.

## Ejecútalo una vez sin instalarlo

```sh
npx turno-cli demo
pnpm dlx turno-cli demo
bunx turno-cli demo
```

`turno demo` funciona desde ahí, en un HOME desechable. Los comandos que escriben lanzadores o la status line se niegan a correr desde una copia temporal, porque el ejecutor puede borrar su caché en cualquier momento: instala turno primero.

## Linux

En Linux también funciona: los secretos MCP van al Secret Service (`secret-tool`, de libsecret), el gateway corre como una unidad de `systemd --user` y los enlaces se abren con `xdg-open`.

## El paquete del navegador (opcional)

`turno-browser` es un paquete aparte que no se instala con turno; turno funciona sin él. Instálalo solo si quieres que un agente maneje tu Chrome con sesión iniciada ([guía](/es/docs/guides/signed-in-browser), en inglés).

## Autocompletado (opcional)

```sh
echo 'source <(turno completion zsh)' >> ~/.zshrc
echo 'eval "$(turno completion bash)"' >> ~/.bashrc
turno completion fish > ~/.config/fish/completions/turno.fish
```

Completa comandos, perfiles, identidades y claves de configuración.

## Actualizar

```sh
# ¿hay una versión más nueva?
turno upgrade --check
# actualiza turno de la misma forma en que lo instalaste
turno upgrade
```

Los comandos interactivos le preguntan al registro de npm si hay una versión más nueva, como máximo una vez al día, y solo envían el nombre del paquete. Lo apagas con `update_check = false` en config.toml o con `TURNO_NO_UPDATE_CHECK=1`.

## Desinstalar

```sh
# muestra lo que turno configuró: servicio, lanzadores, entradas MCP, status line, configuración
turno uninstall --dry-run
# lo quita
turno uninstall
# o: pnpm remove --global, bun remove --global, yarn global remove, brew uninstall turno
npm uninstall --global turno-cli
```

Las carpetas de los perfiles, que guardan tus credenciales, se quedan hasta que tú las borres. `turno uninstall --purge` también borra el estado y las cachés de turno (copias, registros, uso, servidores MCP instalados), y después `turno undo` ya no tiene qué restaurar.
