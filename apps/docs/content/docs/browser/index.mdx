---
title: "turno-browser"
description: "A browser your agents use with your accounts. It stays light on your machine, and the model never sees your passwords."
---

turno-browser is an MCP server that lets a coding agent drive the Google Chrome installed on your machine, with one persistent profile per identity. You sign in to a site once, by hand, and the agent works in that same signed-in browser afterwards.

It is its own package and works without turno. With turno, the gateway runs one browser server for every session of every agent.

```sh
npm install --global turno-browser
turno-browser init
```

`init` asks a name for the identity, opens Chrome so you sign in by hand, and gives the identity to your agent. [Get started](/docs/browser/get-started) shows a whole run, and the same steps one command at a time.

## What it does

| The problem | What turno-browser does | Read |
|---|---|---|
| Your agent opens a browser that is not signed in | each identity is a real Chrome profile that keeps its cookies | [Identities and settings](/docs/browser/identities) |
| A browser left open eats the machine | pages are capped, parked and closed, and Chrome closes when no agent calls it | [Tabs and lifecycle](/docs/browser/tabs) |
| Passwords should not pass through a model | a vault in the system keychain fills a sign-in form, and the agent never sees the values | [Vault, sign-in and secrets](/docs/browser/vault) |
