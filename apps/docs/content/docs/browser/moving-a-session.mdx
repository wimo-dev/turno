---
title: "Moving a session"
description: "Take an identity's signed-in session to another machine in one encrypted file."
---

```sh
turno-browser export school --out school.session --expires 2d
turno-browser import school.session --as school-laptop
```

The export holds the identity's cookies, localStorage and IndexedDB, encrypted with a passphrase you type (asked twice, or the first line of stdin), and is refused after its expiry (7 days by default, at most 90). It never holds vault credentials. Importing into an identity that exists replaces its session, so turno asks first (or needs `--yes`).

Without the `keychain` key Chrome encrypts an identity's cookies with a fixed key that is the same on every machine, so the profile folder is as sensitive as the sessions in it. `"keychain": "system"` in identity.json makes Chrome use the macOS Keychain or the Linux Secret Service instead. On macOS, an identity you create at a terminal with Google Chrome gets `"keychain": "system"` written by `turno-browser add`; existing identities keep the key they have. Changing it signs the identity out (its cookies were encrypted with the other key): export first and import after.
