title: "Get started"
description: "Install turno-browser and let turno-browser init set it up: an identity, a sign-in by hand and your agent."
---

turno-browser works on its own: you do not need turno to use it. It needs Node 22.11 or newer (or the [standalone executable](#install-without-node), which needs no Node) and a Chromium-based browser on the machine: Google Chrome, or Microsoft Edge, Brave or Chromium ([Choosing the browser](/docs/browser/identities#choosing-the-browser)). It downloads no browser unless you ask: on a machine with none, and no admin password to install one, `turno-browser install-browser` puts Chrome for Testing in your user cache.

## Install

```sh
npm install --global turno-browser
```

This installs two commands: `turno-browser`, which manages identities, and `turno-browser-mcp`, the MCP server an agent runs for one identity.

### On Windows

turno-browser runs on Windows 10 and 11 (x64) too. Install it the same way, from PowerShell or the Command Prompt, with no admin rights:

```powershell
npm install --global turno-browser
```

- **Browsers.** It finds Google Chrome, Microsoft Edge and Brave in `Program Files`, `Program Files (x86)` and, for an install for your user alone, `%LOCALAPPDATA%`. With none of them, `turno-browser install-browser` puts Chrome for Testing in `%LOCALAPPDATA%\ms-playwright`, and `winget install --id Google.Chrome.EXE --scope user` installs Chrome for your user alone.
- **Your data.** Identities and their profiles go to `%LOCALAPPDATA%\turno\data\browser`, settings to `%APPDATA%\turno` and runtime state to `%LOCALAPPDATA%\turno\state`. `TURNO_CONFIG_DIR`, `TURNO_STATE_DIR` and `TURNO_DATA_DIR`, or the `XDG_*` variables, move them as on Linux. [Identities](/docs/browser/identities#on-windows) has the details.
- **Agents.** npm installs `turno-browser-mcp` as a `.cmd` file, which a program can start only through `cmd.exe`, so `setup` and `init` register it as `cmd /c turno-browser-mcp --identity <id>`.
- **Not on Windows yet:** proxy passwords and the [vault](/docs/browser/vault) (turno-browser has no secret store there), and Lightpanda, which has no Windows build. Camoufox runs when `TURNO_CAMOUFOX_PATH` names its `camoufox.exe`. turno itself (`turno-cli`) does not install on Windows: npm refuses it.

What was checked: the test suite, including the tests that start a real Google Chrome, on GitHub's `windows-latest` runner with Node 22 and 24, and an npm install of the packages followed by `install-browser` and `doctor`'s test launch. Edge and Brave are detected there but were not launched, and nobody has tried it by hand on a Windows 10 or 11 desktop or on ARM64 yet.

## Install without Node

On a machine without Node or npm, use the standalone executable: one file that holds turno-browser and the Node.js runtime it needs. It still drives the Chrome, Edge or Brave installed on the machine, or the Chrome for Testing that `turno-browser install-browser` puts in your user cache. The GitHub release of each turno-browser version, tagged `turno-browser@<version>` on the [releases page](https://github.com/wimo-dev/turno/releases), has one archive per platform and a `SHA256SUMS` file:

| Platform | Archive |
|---|---|
| macOS, Apple silicon | `turno-browser-darwin-arm64.zip` |
| macOS, Intel | `turno-browser-darwin-x64.zip` |
| Linux, x64 | `turno-browser-linux-x64.zip` |
| Windows, x64 (experimental) | `turno-browser-win-x64.zip` |

Windows is experimental: turno-browser does not support Windows yet, so that executable is published for testing and may not work.

Each archive holds the executable (`turno-browser`, or `turno-browser.exe`) and its license files. The one executable is both programs: `turno-browser <command>` is the CLI, and `turno-browser mcp` is the MCP server that `turno-browser-mcp` is in the npm package.

```sh
version=0.9.0   # the version you want
platform=darwin-arm64
base="https://github.com/wimo-dev/turno/releases/download/turno-browser%40$version"
curl -fLO "$base/turno-browser-$platform.zip"
curl -fLO "$base/SHA256SUMS"
```

### Check the download

Compare the archive with `SHA256SUMS`:

```sh
shasum -a 256 -c SHA256SUMS --ignore-missing     # macOS
sha256sum -c SHA256SUMS --ignore-missing         # Linux
```

On Windows, `Get-FileHash .\turno-browser-win-x64.zip -Algorithm SHA256` in PowerShell prints the hash to compare with the line in `SHA256SUMS`.

Each archive also has a build provenance attestation: a signed record that the release workflow of this repository built it. With the [GitHub CLI](https://cli.github.com):

```sh
gh attestation verify turno-browser-darwin-arm64.zip --repo wimo-dev/turno
```

### Put it in place

Unzip the archive and move the executable to a folder you keep, for example `~/.local/bin` (add that folder to your `PATH` to type just `turno-browser`):

```sh
unzip turno-browser-darwin-arm64.zip turno-browser
mkdir -p ~/.local/bin && mv turno-browser ~/.local/bin/
~/.local/bin/turno-browser --version
```

`turno-browser setup` and `init` give the agent this executable by its full path (`<path>/turno-browser mcp --identity <id>`), so after moving it, run `setup` again. To update, replace the file with the one from a newer release; the identities stay.

**macOS.** The executable is not signed with an Apple Developer ID yet, so Gatekeeper refuses to open a copy that a browser downloaded. A file fetched with `curl`, as above, is not marked and runs as it is. For a browser download, remove the mark in Terminal:

```sh
xattr -d com.apple.quarantine ~/.local/bin/turno-browser
```

or, after the first refusal, open System Settings, Privacy & Security, and click Open Anyway next to the message about `turno-browser` (on macOS 14 and older, Control-click the file in Finder and choose Open).

**Windows.** The executable is not Authenticode-signed yet, so SmartScreen may warn that it is unrecognized: choose More info, then Run anyway. In PowerShell, `Unblock-File .\turno-browser.exe` removes the downloaded-from-the-internet mark before the first run.

### Where it keeps its data

The same places as the npm package, so the standalone executable and an npm install share the identities: profiles and settings under `~/.local/share/turno/browser/` (or `$XDG_DATA_HOME/turno/browser/`), and Chrome for Testing, when you install it, in the Playwright cache (`~/Library/Caches/ms-playwright` on macOS, `~/.cache/ms-playwright` on Linux, or `PLAYWRIGHT_BROWSERS_PATH`). The executable itself writes nothing next to itself.

## Set it up

```sh
turno-browser init
```

`init` asks at each step and does three things: it creates an identity, opens Chrome so you sign in by hand, and gives the identity to your agent. Ctrl-C stops at any step, and each step that is done stays done.

```text
Set up turno-browser: a browser identity, signed in once, given to your agent.
Ctrl-C stops at any step; each step that is done stays done.

Step 1 of 3  the identity
An identity is one Chrome profile your agent uses, with your sign-ins. Name it after what it is for.
Name [personal]: school
Created "school" at ~/.local/share/turno/browser/identities/school

Step 2 of 3  sign in by hand once
Chrome opens on this identity's profile. Sign in to the sites your agent needs, then close the window.
First site to open (Enter for none): mail.example.com
Open Chrome now? [Y/n]
Saved. Sites you opened: mail.example.com. The agent starts with the same cookies on them.

Step 3 of 3  give it to your agent
Agents found here: claude-code (Claude Code)
Agents: claude-code, codex, cursor, copilot, gemini, json, or none.
Agent [claude-code]:
This adds the browser to Claude Code:
  claude mcp add --scope user browser-school -- turno-browser-mcp --identity school
Run it now? [Y/n]
Done: Claude Code has the browser "school".

Next
Start a new Claude Code session and ask it to open https://mail.example.com.
turno-browser doctor checks Chrome and the identity; turno-browser show school shows its settings.
```

It runs the agent's own `mcp add` command only if you say yes. Cursor and `json` have no such command, so `init` prints the block to paste. `--identity`, `--agent`, `--url`, `--no-login`, `--yes` and `--dry-run` answer the questions ahead; without a terminal (a pipe, or an agent's session) it needs `--identity` and `--agent`, skips the sign-in and prints the agent's command instead of running it.

The rest of this page does the same three steps one command at a time.

## Add an identity

An identity is one persistent Chrome profile. Give it a name you will recognize:

```sh
turno-browser add school
```

```text
identity "school" ready at ~/.local/share/turno/browser/identities/school
settings (time zone, languages, health check) in ~/.local/share/turno/browser/identities/school.json

Next:
  turno-browser login school
      sign in to your sites by hand once; the cookies stay in the profile
  turno-browser setup claude-code --identity school
      prints how Claude Code gets this browser (also codex, cursor, copilot, gemini, json)
Any other MCP client runs: turno-browser-mcp --identity school
```

## Sign in once

```sh
turno-browser login school
```

The identity's Chrome opens on a short page that says what to do. Sign in to your sites by hand, then close the window. `--url https://mail.example.com` opens a site directly.

```text
Saved. Sites you opened: mail.example.com. The agent starts with the same cookies on them.
```

The cookies stay in that profile, so the agent starts signed in. The profile now holds live sessions: treat its folder as credentials.

## Give it to your agent

`turno-browser setup` prints how one agent gets the identity. It writes nothing: you run the command or paste the block yourself.

```sh
turno-browser setup claude-code --identity school
```

```text
Run this once to give Claude Code the browser identity "school":

claude mcp add --scope user browser-school -- turno-browser-mcp --identity school

--scope user adds it to every project; leave it out to add it to the current folder only.
Start a new agent session to load it. Sign in to your sites once with turno-browser login school.
```

| Agent | `setup` prints |
|---|---|
| `claude-code` | a `claude mcp add` command |
| `codex` | a `[mcp_servers]` block for `~/.codex/config.toml`, and the `codex mcp add` command |
| `cursor` | an `mcpServers` entry for `~/.cursor/mcp.json` |
| `copilot` | an `mcpServers` entry for `~/.copilot/mcp-config.json`, and the `copilot mcp add` command |
| `gemini` | an `mcpServers` entry for `~/.gemini/settings.json`, and the `gemini mcp add` command |
| `json` | the generic `mcpServers` entry other MCP clients read |

Without `--identity` it uses the only identity there is.

## The first call

Start a new agent session and ask it to open a site you signed in to. The agent calls `browser_navigate`, Chrome opens on the identity's profile, and the page is already signed in.

You can also try it from a terminal, without an agent:

```sh
# starts the background server if needed
turno-browser do school open https://example.com
# the page's tree, with refs like e12
turno-browser do school snapshot
turno-browser do school end
```

[Actions and the shell](/docs/browser/actions#from-the-shell) has every action of `do`.

## Shell completion (optional)

```sh
echo 'source <(turno-browser completion zsh)' >> ~/.zshrc
echo 'eval "$(turno-browser completion bash)"' >> ~/.bashrc
turno-browser completion fish > ~/.config/fish/completions/turno-browser.fish
```

## With turno

If you use turno, its gateway runs the browser server for you: one server for every session of every agent, stopped when nobody uses it. turno has its own wizard, `turno init`; `turno-browser init` is for turno-browser on its own.

```sh
npm install --global turno-cli turno-browser
# the identity, and its mcp.toml entry
turno identity add browser:school
turno identity login browser:school
```

With turno installed, every `turno-browser <command>` on these pages also runs as `turno browser <command>`. The guide [Let an agent use my signed-in browser](/docs/guides/signed-in-browser) goes through it.
