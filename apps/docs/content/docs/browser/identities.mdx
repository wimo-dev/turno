title: "Identities and settings"
description: "A browser identity is one persistent Chrome profile that an agent drives, with settings that stay the same between sessions."

This page explains what a browser identity is, what stays the same about it from one session to the next, and how to check that it is healthy. To set one up, follow [Get started](/docs/browser/get-started).

## One identity, one Chrome profile

`turno-browser` drives the Google Chrome you have installed (or [another Chromium-based browser](#choosing-the-browser)), headed, with a persistent user data folder per identity. You sign into a site once by hand; the cookies stay in that identity's profile, and the agent works there afterwards.

```sh
# a new identity, and how to connect an agent to it
turno-browser add school
# sign in by hand once; cookies persist
turno-browser login school
turno-browser list
```

Identities live under `~/.local/share/turno/browser/` (on Windows, `%LOCALAPPDATA%\turno\data\browser\`). They hold live cookies of the sites you signed into: treat that folder as credentials.

### On Windows

| What | Where |
|---|---|
| Identities, profiles, flows, recordings | `%LOCALAPPDATA%\turno\data\browser` |
| Settings | `%APPDATA%\turno` |
| Runtime locks, background server state, logs | `%LOCALAPPDATA%\turno\state` |

`TURNO_DATA_DIR`, `TURNO_CONFIG_DIR` and `TURNO_STATE_DIR` (or `XDG_DATA_HOME`, `XDG_CONFIG_HOME` and `XDG_STATE_HOME`) move them as on macOS and Linux.

The background server listens on a named pipe, `\\.\pipe\turno-browser-<id>-<hash>`, instead of a socket file. By default Windows lets only your user, the administrators and the system account write to a pipe like it, so nobody else can send it a request. The hash comes from the state folder, so two turno folders never share a pipe. When another program already holds that name, the server listens on `127.0.0.1` instead, with a bearer token kept in your state folder. Windows has no signals, so `background stop` asks the server to stop over its own pipe, and a holder that does not answer is ended with `taskkill /PID <pid> /T /F`, which ends its Chrome with it.

## Settings that do not change

Each identity keeps an `identity.json` next to its profile with what should stay the same between sessions: time zone, languages, locale and region.

```sh
# pinned to this time zone
turno-browser add school --languages es-ES,es,en
turno-browser set school --timezone Europe/Madrid
turno-browser show school
```

`show` prints the settings and the state of one identity:

```text
browser:school
  profile       ~/.local/share/turno/browser/identities/school
  settings      ~/.local/share/turno/browser/identities/school.json
  time zone     Europe/Madrid
  languages     es-ES, es, en
  health check  the one login finds, if any (to set one: turno-browser set school --health-url <url> --health-text <text>)
  agent cursor  shown when the browser can be seen: a window, or the live view (auto)
  created       2026-11-20 08:41
  updated       2026-11-20 08:43
  last sign-in  never by hand (turno-browser login school)
  state         not in use
defaults (not in identity.json; decided at every launch):
  live: on (default)
  resources: auto (auto: the low-resource preset while memory is short)
  humanize: auto (default)
  sharing: tabs (default)
  ...
```

The [agent cursor](/docs/browser/agent-cursor) row is the `cursor` setting. They are applied at every Chrome start, the way a person's own Chrome would get them, so pages, frames and workers all read the same values: languages go to Chrome's own `--accept-lang`, the locale to `--lang` (and to `LANG` on Linux), and the time zone to the `TZ` of Chrome's process when it differs from the machine's (on Windows, where Chrome does not read `TZ`, it is emulated). Without a locale or languages, Chrome reads the system's language itself, as it does for a person, so a page sees the same languages as in your own Chrome on this computer. On macOS Chrome formats dates and numbers (`Intl`) in the system's language whatever the locale says; a locale other than the system's changes the languages a site reads, not the format.

## Defaults

Every feature has a default that turno works out when Chrome starts, from what it knows then: headless or with a window, the live view, memory pressure, the engine and the policy. The defaults are never written into `identity.json`: the file holds only what you chose, so a key you leave out follows the default of the turno-browser you run. `show`, `status` and `doctor` list each value with where it came from, for example `resources: low (auto: memory pressure)`.

| Feature | Default | When |
|---|---|---|
| [Live view](/docs/browser/live-view) | on | every server with an identity; it opens only when you ask |
| [Flows](/docs/browser/flows) | recorded | always |
| [Screenshots](/docs/browser/flows#recordings-and-traces) | after each action, under a disk cap | never of a page that shows a vault value; not in attach or read mode |
| [Traces](/docs/browser/flows#recordings-and-traces) | off (not yet available: while tracing, Chrome loads no image or frame of another site) | `--record-traces true` turns them on |
| `vision`, `pdf`, `devtools`, `network` tools | listed | `devtools` not with `record.traces: true`; `network` not when the policy turns it off |
| [`storage` tools](/docs/browser/vault#cookies-and-stored-tokens) | listed, session values masked | not in attach mode or when the policy turns it off |
| [Vault submit](/docs/browser/vault) | `auto` | `confirm` when you chose it, or when the policy says `autoSubmit: false` |
| [Low-resource preset](/docs/browser/tabs#low-resource-mode) | `auto` | on while the system reports memory pressure |
| Background throttling | on | headless without the live view |
| [Human-like input](/docs/browser/actions#human-like-input) | `auto` | off on localhost and for reading, light to act, full on sign-in, payment and support pages and challenged sites |
| [Tab sharing](/docs/browser/sharing) | `tabs` | `session` in attach mode |
| [Coherent user agent](/docs/browser/network#a-coherent-user-agent) | on | headless Chrome only, once `login` has read that Chrome's client hints |
| Locale | the system's, read by Chrome itself | when `identity.json` has no locale or languages |
| Cookie key | the system keychain | new identities created at a terminal on macOS with Google Chrome |
| [Health check](#session-health) | the one `login` finds | when `identity.json` has none |
| [Natural language actions](/docs/browser/natural-language-and-captchas#which-model-answers) | on | when the client offers MCP sampling, an API key is in the environment, or the Claude Code CLI or Codex is on the PATH; off when the policy turns them off |
| [Proxy](/docs/browser/network#the-systems-proxy) | the system's | when `identity.json` has none; `--proxy-server off` connects directly |
| [Captcha solving](/docs/browser/natural-language-and-captchas#captcha-solving) | a person answers | solved when `TURNO_BROWSER_CAPTCHA_ENDPOINT` and `TURNO_BROWSER_CAPTCHA_KEY` are set |

To keep a default from applying, set the key: a value, or for a key with no off value of its own, `off` (format 14 of `identity.json`):

```sh
turno-browser set school --live false --record-flows false --sharing session
turno-browser set school --user-agent off --locale off --health off
# back to the default
turno-browser set school --live "" --user-agent ""
```

`"auto"` (for `live.enabled`, `resources`, `humanize.level` and `userAgent`) says the same as leaving the key out. A file with an `auto` or `false` value is written as format 14, which an older turno-browser refuses with "update turno-browser" instead of guessing.

Some features stay one step away: resource blocking and the own HTTP cache (`--block-*`, `--cache`), `--allow-http-identity`, and the [engines](/docs/browser/engines) other than Chrome. `turno-browser add` offers Camoufox and Lightpanda when they are installed, and attach mode, but never switches an identity on its own. Natural language actions, captcha solving, `storage` and the proxy stay off until you set them.

The locale also picks the language of what a person sees in the browser: the [live view](/docs/browser/live-view) page, the banner and Done button of a person step (`browser_request_human`), the [agent cursor](/docs/browser/agent-cursor)'s badge and the page `turno-browser login` opens. A Spanish locale (`es`, `es-MX`, `es-419`) shows them in Spanish; any other locale, or none, in English. Without a locale, the first entry of `languages` decides. Tool results, tool descriptions and CLI output stay in English, since agents and developers read them.

```sh
turno-browser set school --locale es-MX
```

## Policy

An identity can also carry a [policy](/docs/browser/policy): the hosts its tabs may show, features that do not exist for it (captcha solving, natural language actions, scripts) and whether `browser_login` may submit. Only the command line writes it (`turno-browser set <id> --policy-file <file>`, or `init --policy-file`), and no agent tool can change it.

## Choosing the browser

An identity's profile opens in Google Chrome unless its `identity.json` names another
Chromium-based browser (`browser`, format 13). Every command uses it: the agent's server, `login`,
`export` and `import`, the background server and `replay`.

```sh
# a new identity on Brave
turno-browser add school --browser brave
# the installed browsers, and which one each identity uses
turno-browser doctor
```

| `browser` | What opens the profile | Checked on macOS |
|---|---|---|
| `chrome` (default) | Google Chrome, in /Applications or ~/Applications | Chrome 157 and 158 |
| `edge` | Microsoft Edge | Edge 158 |
| `brave` | Brave | Brave 157 |
| `chrome-for-testing` | the build `turno-browser install-browser` downloads into your user cache | Chrome for Testing 156 |
| `chromium` | a Chromium installed on the machine (Chromium.app, or a distribution's package; not a snap) | not checked |
| an absolute path | any other Chromium-based browser | may work |

"Checked" means turno launched it on a persistent profile, headed and headless, and the agent's
tools, the [live view](/docs/browser/live-view)'s picture and the [agent cursor](/docs/browser/agent-cursor)
worked, with cookies kept from one start to the next. Arc and Dia are Chromium builds turno has
not tested: give their path if you want to try one. On Linux turno looks in the packages' usual
places (`/opt/google/chrome`, `/opt/microsoft/msedge`, `/opt/brave.com/brave`, `/usr/bin`). On
Windows it looks in `Program Files`, `Program Files (x86)` and `%LOCALAPPDATA%` (where a browser
installed for your user alone goes), and reads the version from the folder next to the browser
instead of starting it.

When Google Chrome is not installed, `add` and `init` pick the first browser they find and write
it to `identity.json`, so the profile never changes browser by itself. A server's own `--browser`
or `--executable-path` wins over `identity.json` for that server.

### No browser, and no admin password

```sh
turno-browser install-browser
turno-browser set school --browser chrome-for-testing
```

`install-browser` downloads Chrome for Testing, the Chrome build Google publishes for automation,
with the installer of the Playwright build turno-browser uses: about 190 MB into your user cache
(`~/Library/Caches/ms-playwright` on macOS, `~/.cache/ms-playwright` on Linux,
`%LOCALAPPDATA%\ms-playwright` on Windows, or `PLAYWRIGHT_BROWSERS_PATH`). It needs no admin password and changes nothing outside that folder.
Its limits: it does not update itself (run the command again after you update turno-browser), it
can be a version behind Chrome, and Google publishes it for testing, not as an everyday browser.
Google's sign-in page loaded in it as in Chrome and Brave when turno tried it.

On macOS, Google Chrome itself also runs from `~/Applications`, which needs no admin password:
open Google's disk image and drag Chrome into the Applications folder of your home folder.
turno finds it there.

### Changing the browser of an identity

`turno-browser set <id> --browser <name>` on a profile no browser has opened yet just changes the
setting. On a profile another browser already opened it is refused unless you add `--force`:

- With the default keychain, the cookies carried over in every direction turno tried (Chrome,
  Brave, Edge and Chrome for Testing, even from Chrome 157 to Chrome for Testing 156).
- But the new browser rewrites the profile (Brave adds its own components and settings, which stay
  when you switch back), and an older browser can refuse a profile a newer one upgraded.
- With `keychain: "system"` each browser encrypts cookies with its own key, so the new browser
  cannot read the sign-ins: sign in again.

To keep things simple, make a new identity for the other browser and sign in there. `doctor` warns
when a newer browser than the identity's last opened its profile.

## One Chrome per identity

While a server drives an identity's Chrome it holds a runtime lock. A second session on the same identity gets an error that names the process holding it and how to stop it, instead of Chrome's "Browser is already in use". That is also why an identity is declared as a `shared`, `exclusive` server ([Scopes](/docs/concepts/scopes#exclusive-shared-one-session-at-a-time)): one agent session uses it at a time, unless you turn on tab sharing.

## Session health

A health check names a page and what it shows only when signed in:

```sh
turno-browser set school --health-url https://mail.example.com/ --health-text Inbox
```

When Chrome starts (at most every 30 minutes while it passes) turno checks it. If the proof is missing, the identity is `NEEDS_AUTH`: tool calls fail with a message that asks you to run `turno-browser login <id>`.

Without a check of yours, `turno-browser login` finds one: the last page you opened that showed a sign-out link becomes the check, kept in the identity's state folder and not in `identity.json`. Since it is a guess, a failed found check is reported (the server's stderr, `show`, `doctor`) but does not stop tool calls. `--health off` turns off both.

## Reputation log

Each captcha, "verify it's you" or block page the identity meets is one line in its state folder, with the site's host name only: no path, no page content. With [captcha solving](/docs/browser/natural-language-and-captchas#captcha-solving) on, each solve attempt is a line too. The tool result that ends on such a page says so in a `Challenge` section (`turno.challenge` in JSON) and says which way it goes: to `browser_solve_captcha` for a captcha when a solver key is configured, otherwise to the person (`browser_request_human`); nothing is paused.

```sh
# counts per site, and whether they go up or down
turno-browser reputation school
```

## Doctor

```sh
# the browsers installed, a test launch, Lightpanda, Camoufox, and each identity's browser, settings, engine, lock, sign-in and proxy credentials
turno-browser doctor
# clears stale locks, a Chrome left running with no server, and a stray Lightpanda
turno-browser doctor --fix
```

Each finding has its own page under [Troubleshooting](/docs/troubleshooting#turno-browser-doctor).
