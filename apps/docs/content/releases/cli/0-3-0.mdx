turno 0.3.0 is mostly about the browser, in [turno-browser 0.3.0](/releases/browser/0-3-0): it signs in to a site without showing the password to the model, moves a signed-in session to another machine, keeps tabs under control, and tells the agent what blocks a click. The CLI gets **[a stable output contract for scripts](/docs/reference/json-output)**, diagnostics you can paste into an issue, and a safe mode. turno also has a home now: [turno.wimo.dev](https://turno.wimo.dev).

## Upgrade

<Upgrade>

**Update `turno-cli` and `turno-browser` together.** This turno-cli needs turno-browser 0.3, and says so in one line if the other one is older.

**Run `turno mcp sync` once.** Copilot CLI and Cursor CLI gateway entries gained a header.

**Check your scripts.** A few exit codes changed: see [Changed behavior](#changed-behavior).

</Upgrade>

## Highlights

<Highlight area="CLI" title="Output for scripts" href="/docs/reference/json-output" more="JSON output">

Every `--json` object now carries `schemaVersion`, `--json=fields` lists a command's fields and `--json=a,b` keeps only those. Errors under `--json` are one JSON line on stderr. Exit codes are documented and fixed: 0 ok, 1 failure, 2 usage, 3 no profile for the folder, 4 not signed in, 5 mcpd down.

</Highlight>

<Highlight area="CLI" title="Diagnostics and safe mode" href="/docs/troubleshooting" more="Troubleshooting">

Safe mode (`--no-gateway` or `TURNO_SAFE=1`) opens the agent with the profile's account but without the gateway, its token, the status line or the hooks: the fastest way to tell whether a problem is turno's.

```sh
# call a tool as a session would
turno mcp call github list_issues \
  --arg repo=wimo-dev/turno
# a Markdown block for an issue, no secrets
turno doctor --report
# open the agent without turno's gateway
turno run work --no-gateway
```

</Highlight>

## Gateway

- **`turno mcp export`**: prints your `mcp.toml` without secret values and lists the `turno secret set` commands the other machine needs.
- **`turno mcp import`**: merges that export there, or a JSON `mcpServers` file, or a Codex `config.toml`. Remote servers that answer with an OAuth challenge are marked `auth = "oauth"` on the way in.
- **Memory pressure**: under critical memory pressure mcpd stops a quiet browser even while its session lives, and `stop_grace` per server sets how long it waits before stopping one.

## CLI

- **Install it your way**: npm, pnpm, bun, yarn and Homebrew are all first-class. `turno upgrade` and `turno version` recognize each one, and a one-off `npx`, `pnpm dlx` or `bunx` run says which command gets the newest release instead of installing turno globally. [Install](/docs/get-started/install).
- **Next steps**: commands that write end with a `Next:` line.

## Packages

- **`turno-core`**: a new package that holds what `turno-cli` and `turno-browser` share: paths, the secret store and process helpers. Nothing changes for you.
- **Homepage**: the packages' homepage is [turno.wimo.dev](https://turno.wimo.dev).

## Changed behavior

What can break a script or a habit when you upgrade from 0.2:

- **`turno auto`**: exits 3 (was 1) when the folder has no profile.
- **`turno mcp daemon status`, `turno mcp top` and `turno mcp savings`**: exit 5 (was 1) when mcpd is down.
- **Gateway entries of Copilot CLI and Cursor CLI**: gained a header. Run `turno mcp sync` once after upgrading.
