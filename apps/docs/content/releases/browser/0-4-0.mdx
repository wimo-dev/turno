One browser identity can now **[serve several agents at once](/docs/browser/sharing)**, each in its own tabs. What an agent does can be **[saved as a flow and replayed](/docs/browser/flows#flows-record-and-replay)**, coding agents can **[drive the browser from the shell](/docs/browser/actions#from-the-shell)**, and you can **[watch the agent's tab and take over](/docs/browser/live-view)** when a site needs a person. Two **[engines](/docs/browser/engines)** join Chrome: Lightpanda for reading pages with little memory, and your own Chrome. Every new setting is off until you turn it on. It came out with [turno 0.4.0](/releases/cli/0-4-0).

## Upgrade

<Upgrade>

**Nothing to migrate.** Your `identity.json` files keep working as they are. An identity that turns on a new setting is written in a newer format, which an older turno-browser on another machine refuses with a message to update it.

</Upgrade>

## Highlights

<Highlight area="Browser" title="Several agents, one browser" href="/docs/browser/sharing">

Until now an identity served one agent session at a time. With `"sharing": "tabs"` several sessions use the same signed-in browser, each with its own current tab and the tabs it holds. Another session's call on a held tab waits up to 10 seconds and then fails with a message that names the holder, `browser_close` closes only the calling session's tabs, and a session lets go of its tabs when it ends or after 5 minutes without a call.

```sh
turno browser set school --sharing tabs
turno browser set school \
  --tab-lock-wait 30s --tab-lock-release 10m
```

Serve the identity with `exclusive = false` in `mcp.toml`; `turno browser doctor` warns when the two disagree.

</Highlight>

<Highlight area="Browser" title="Record a flow once, replay it" href="/docs/browser/flows#flows-record-and-replay" more="Flows: record and replay">

`browser_record` saves what an agent does as a named flow. Each element is kept four ways (Playwright's locator, role and name, text and CSS path), so a small change on the page does not break it, and typed text becomes parameters. Passwords, one-time codes and values marked sensitive are never saved. `browser_replay` runs the flow, and when a step no longer fits it stops with a report the agent can continue from.

```sh
# saved flows and their parameters
turno browser flows school
turno browser replay school sign-in \
  --param password=keychain:school-password
# record every session, with traces
turno browser record school --flows --traces
```

</Highlight>

<Highlight area="Browser" title="Drive the browser from the shell" href="/docs/browser/actions#from-the-shell" more="From the shell">

Some coding agents prefer commands to MCP tools. `turno browser do` runs one browser action per command through mcpd, with the same tab locks, vault, recordings and refusals an agent gets over MCP. The commands one agent or one shell runs share a session and keep their tab until `end`. The Claude Code plugin adds a short `browser-identity` skill that teaches the loop.

```sh
turno browser do school open \
  https://mail.example.com/
# refs like e12
turno browser do school snapshot
turno browser do school click e12
turno browser do school end
```

</Highlight>

<Highlight area="Browser" title="Watch the agent and take over" href="/docs/browser/live-view" more="Live view and take-over">

Off by default. With `--live true` turno-browser serves a view of the agent's tab on 127.0.0.1, behind a link that works once and is never printed. Pause the agent, solve what needs a person (a sign-in, a confirmation), and resume: each held call is told what changed, and a call that would act on a stale page gets a fresh snapshot instead. A page that holds a vault value or a password is never shown.

```sh
turno browser set school --live true
# opens the view
turno browser live school
# holds the next call
turno browser pause school
turno browser resume school
```

</Highlight>

<Highlight area="Browser" title="Two more engines" href="/docs/browser/engines" more="Engines">

Read mode runs an identity on [Lightpanda](https://github.com/lightpanda-io/browser) instead of Chrome, to read pages with a fraction of the memory; tools that need a laid-out page are refused with the reason. Attach mode connects to the Chrome you already have open, works in a tab of its own and never closes yours. turno never downloads either engine, and `turno browser doctor` checks both.

```sh
# read mode
turno browser set research --engine lightpanda
# your own Chrome, with remote debugging on
turno browser set school --attach auto
```

</Highlight>

## Off by default

These settings exist for the cases where a site needs them. Each one is off until you turn it on per identity, and each has its own section with what it costs.

- **[Human-like input](/docs/browser/actions#human-like-input)**: `--humanize light|full|adaptive` moves the pointer along a curve, holds the button and types key by key. Tool names and results do not change.
- **[Natural language actions](/docs/browser/natural-language-and-captchas#natural-language-actions)**: `--act` adds `browser_act`, `browser_extract` and `browser_observe`, which run on your client's model through MCP sampling or on a chat completions API you name. The model sees a snapshot with vault values and password fields hidden, and can only use the stock actions on the current tab, every step shown.
- **[Captcha solving](/docs/browser/natural-language-and-captchas#captcha-solving)**: `--captcha-provider` sends a reCAPTCHA, hCaptcha or Turnstile widget to a solver service you name. The service sees the page, and solving a site's captchas by machine may break its terms: it is for your own accounts.
- **[Network and user agent](/docs/browser/network#network-and-user-agent)**: a coherent user agent for headless Chrome, checked against its client hints, headers, languages and time zone at launch, and a proxy per identity with its password only in the secret store.
- **[Camoufox](/docs/browser/engines#camoufox)**: runs an identity on an installed Camoufox through stock Playwright, with its own Firefox profile.

Keys for these services are only `keychain:` references, read from the secret store when used and hidden from every result. See [Acceptable use](/docs/browser/natural-language-and-captchas#acceptable-use).

## Browser

- **Faster errors**: when another element covers the target of a click, and still covers it 300 ms later, the error names that element at once instead of after the 5 second timeout.
- **No more closed-page errors**: a tool call waits for the tab governor to finish closing a popup or a parked tab.
- **Cleanup**: a server in read mode stops a Lightpanda that a killed server left running, and `turno browser doctor --fix` does too.
- **Benchmarks**: an [evaluation suite](/docs/benchmarks#evaluation-suite) of browser tasks with paired runs, and a [fingerprint and event bench](/docs/benchmarks#fingerprint-and-event-bench) that shows what a page can observe about the browser.

## Changed behavior

What can change when you upgrade from 0.3:

- **Third-party storage partitioning**: Chrome now keeps it on, as a person's Chrome does. Playwright turns it off, and turno used to as well, so a site embedded in another one now sees storage of its own there.
