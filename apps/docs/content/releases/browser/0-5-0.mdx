turno is becoming a set of tools, and **[turno-browser](/browser)** 0.5.0 gets a life of its own. It installs and runs without turno: **[its own `turno-browser` command](/docs/browser/get-started)** creates identities and signs in, **[`turno-browser setup`](/docs/browser/get-started#give-it-to-your-agent)** prints the line that gives an identity to Claude Code, Codex, Cursor, Copilot CLI or Gemini CLI, and **[`turno-browser do`](/docs/browser/actions#from-the-shell)** drives the browser from the shell through a background server of its own. The browser also has **[its own docs](/docs/browser)** and a **[comparison with other browser tools](/docs/browser/alternatives)**.

## Upgrade

<Upgrade>

**Nothing to migrate.** Identities, `identity.json` and `mcp.toml` stay as they are.

</Upgrade>

## Highlights

<Highlight area="Browser" title="turno-browser on its own" href="/docs/browser/get-started" more="Get started">

`npm install --global turno-browser` now brings a `turno-browser` command with everything `turno browser` does: identities, sign-in, the vault, moving a session, flows and recordings, the live view, the doctor and the reputation log. turno-cli is not needed.

```sh
npm install --global turno-browser
turno-browser add school
# sign in by hand once
turno-browser login school
```

</Highlight>

<Highlight area="Browser" title="One line for each agent" href="/docs/browser/get-started#give-it-to-your-agent" more="Give it to your agent">

`turno-browser setup` prints the command or the config block that gives an identity to Claude Code, Codex, Cursor, Copilot CLI, Gemini CLI or any MCP client. It never writes your config files; you run or paste what it prints.

```sh
turno-browser setup claude-code --identity school
turno-browser setup codex --identity school
turno-browser setup json --identity school
```

</Highlight>

<Highlight area="Browser" title="Shell actions without the gateway" href="/docs/browser/actions#from-the-shell" more="From the shell">

Without turno, `turno-browser do` starts a background server for the identity on its first action. It listens on a private socket only your user can open, keeps the session and its tab between commands, and exits after 15 minutes without a request. An agent's server for the same identity is refused with a message that says how to stop the background one, so there is never a second Chrome on one profile.

```sh
turno-browser do school open \
  https://mail.example.com/
turno-browser do school snapshot
turno-browser background status school
turno-browser background stop school
```

</Highlight>

<Highlight area="Browser" title="Secrets without turno" href="/docs/browser/vault#secrets" more="Secrets">

`turno-browser secret` sets, checks, lists and removes the secrets that `keychain:` references in `identity.json` point to (a replay parameter, a proxy password, an API key). They are the same items `turno secret` stores, in the OS secret store, and their values are never printed.

</Highlight>

## More

- **Hints that follow the command you ran**: errors, doctor fixes and next steps say `turno-browser ...` when you run turno-browser and `turno browser ...` when you run turno.
- **Doctor**: shows a background server running for an identity.
- **Human-like input on a busy machine**: the steps before an action (reading the field, aiming at the element) now wait up to 3 seconds instead of 1, so a slow machine no longer falls back to a plain fill or click.
- **Wording**: the help no longer labels the settings that are off by default as "not recommended". They stay off until you turn them on, and their docs keep saying what each one sends and to whom.
- **npm and the MCP Registry**: the package description and registry entry say what turno-browser is: a browser your agents use with your accounts, light on your machine, where the model never sees your passwords.
