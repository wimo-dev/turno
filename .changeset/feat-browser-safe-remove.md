Behavior change: `turno-browser remove <id>` (and `turno browser remove`, `turno identity remove browser:<id>`) now asks before it deletes anything, showing the list of what goes. `--yes` skips the question; without a terminal and without `--yes` it refuses with exit code 2 instead of deleting. It also removes what it used to leave behind: it stops the identity's background server, a Chrome on its profile and the turno-browser-mcp processes started for it (instead of refusing while they run); it takes the identity's MCP server out of each agent that has it with the agent's own command (`claude mcp remove --scope user browser-<id>`, `codex mcp remove`, `copilot mcp remove`, `gemini mcp remove`); it deletes the `keychain:` items identity.json references (proxy, act, captcha) unless another identity or turno's mcp.toml uses them, the vault's credentials even when the vault index is broken, and the session exports it wrote. Chrome's own cookie key (`"keychain": "system"`) is shared with every Chrome profile and is kept. Afterwards it checks that nothing is left and exits 1 when something is. `--json` reports `planned`, `deleted`, `failed`, `left` (each with the step that removes it) and `kept`. `destroy` is another name for `remove`. `turno identity remove browser:<id>` passes `--yes` and `--json` on to turno-browser.
