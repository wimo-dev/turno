"turno-browser": minor
---

New per-identity policy in identity.json (format 13), written only by the command line: `turno-browser set <id> --policy-file <file>` (or `--allowed-domains`, `--disable`, `--auto-submit false`, `--no-policy`), `add` with the same flags, and `init --policy-file <file>` for an onboarding without a terminal. `allowedDomains` (like `example.com`, `*.example.com`, `localhost:*`) checks every main-frame navigation of every tab: `browser_navigate`, `browser_tabs` new, links, forms, scripts and popups are stopped before they leave Chrome, and a redirect to another host is taken back when it commits; the call fails with an error that names the host and the allowed list. Scripts, images and data a page loads from other hosts are not checked. `disabled` removes features from the identity (`act`, `captcha`, `login`, `totp`, `attach`, `evaluate`, `run_code`, `network`): their tools are not listed and are refused, and the settings they need are refused. Any policy turns `browser_run_code_unsafe` off, `allowedDomains` turns the network routing tools off, a tool's file argument inside turno's own folders is refused, and the server refuses to start with a `--caps` whose tools the policy turns off. `autoSubmit: false` keeps `browser_login` from submitting whatever `vault submit` says. `show --json` and `status --json` show the policy. An older turno-browser refuses an identity.json with a policy.
