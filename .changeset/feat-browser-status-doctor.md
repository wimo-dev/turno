New `turno-browser status [<id>] [--json]` (also `turno browser status`): each identity at a glance, read only. It shows the profile, a summary of identity.json (time zone, languages, engine, sharing, humanize, live view, recording, act, captcha, proxy), who holds it, the vault's sites and submit policy, the last sign-in by hand, the host names the profile holds cookies for (never their names or values; not read while Chrome has the profile open, and noted where Node has no `node:sqlite`), when it last served a tool call, and the agents whose config has it. A server now records the time of its last tool call (at most once a minute) in the identity's state folder, `last-used.json`. `doctor` checks that the secret store has an item for each vault credential (a lookup, never the value), and, run as turno-browser, which agents' configs have each identity: a server whose command is gone, one whose identity was deleted, a registration init made that the agent lost, and a config file that cannot be read. Only entries that run turno-browser-mcp count as turno's, so a server merely named `browser-<something>` is left alone by doctor and by `remove`.
