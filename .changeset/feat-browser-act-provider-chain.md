Natural language actions (`browser_act`, `browser_extract`, `browser_observe`) are on whenever a model can answer them, without an identity.json `act` group. The server takes the first that works: MCP sampling when the connected client offers it (decided per connection), else `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` from the environment, else the Claude Code CLI (`claude -p`, `haiku`) or Codex (`codex exec`, `gpt-5.6-terra`) found on the PATH, run headless with your own login; with none of them the tools are not listed. The CLI gets the prompt on its standard input, never on its command line, runs with its tools off and no MCP server loaded, and stops after 90 seconds; `TURNO_BROWSER_ACT_CLI=off` keeps the CLIs out of it. A provider named in identity.json keeps working as before. Captcha solving is on when a solver key is configured, in identity.json or with `TURNO_BROWSER_CAPTCHA_ENDPOINT` and `TURNO_BROWSER_CAPTCHA_KEY` in the environment; without one, a result that ends on a captcha says so and hands the step to the person with `browser_request_human`. `show`, `status` and `doctor` say which path each identity resolves to and why. See [Natural language actions and captcha solving](https://turno.wimo.dev/docs/browser/natural-language-and-captchas).
